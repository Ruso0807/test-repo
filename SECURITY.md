# Чек-лист безопасности (универсальный, для любого стека)

Этот список — база, которую стоит проверять в каждом новом проекте, независимо от языка/фреймворка. Когда определитесь со стеком (Node.js, Python и т.д.), под каждый пункт добавляются конкретные инструменты (линтеры, сканеры зависимостей).

## 1. Секреты и конфигурация
- Никогда не коммитьте пароли, API-ключи, токены в код — только через переменные окружения (`.env`, secrets manager).
- Добавляйте `.env` и файлы с ключами в `.gitignore` **до** первого коммита.
- Push-защита секретов уже включена на этом репозитории — GitHub заблокирует push, если найдёт похожий на ключ текст.

## 2. Входные данные (главный источник взлома)
- Никогда не доверяйте данным от пользователя — ни из форм, ни из URL, ни из API.
- Валидируйте всё на сервере (не только в браузере — клиентскую проверку легко обойти).
- Используйте параметризованные запросы к БД (never string-concat SQL) — защита от SQL-инъекций.
- Экранируйте вывод данных пользователя в HTML — защита от XSS.

## 3. Аутентификация и пароли
- Пароли хранить только хешированными (bcrypt/argon2), никогда в открытом виде.
- Ограничивать число попыток входа (rate limiting) — защита от подбора паролей.
- Использовать HTTPS везде, включая dev/staging, если есть такая возможность.

## 4. Заголовки и конфигурация сервера
- `Content-Security-Policy` — ограничивает, откуда может грузиться код/ресурсы.
- `Strict-Transport-Security` (HSTS) — заставляет браузер всегда ходить по HTTPS.
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` — базовая защита от MIME-sniffing и clickjacking.
- Настраивайте CORS явно (конкретные домены), никогда `*` для приватных API.

## 5. Зависимости
- Регулярно обновляйте зависимости — большинство взломов идёт через старые уязвимые библиотеки.
- Dependabot alerts включены на этом репозитории — GitHub сам предупредит об уязвимостях.

## 6. Обработка ошибок и логи
- Никогда не показывайте пользователю технические детали ошибок (stack trace, SQL-запросы) — только в логах на сервере.
- Не логируйте пароли, токены, персональные данные.

## 7. Загрузка файлов (если есть)
- Проверяйте тип и размер файла на сервере, а не по расширению.
- Храните загруженные файлы вне исполняемых директорий.

## 8. Перед деплоем
- Убедитесь, что режим отладки (`DEBUG=True` и т.п.) выключен в продакшене.
- Ограничьте права доступа (принцип наименьших привилегий) для БД-пользователей, API-ключей.

---
Это базовый ориентир, не исчерпывающий список. При выборе конкретного стека — попроси меня настроить под него линтеры безопасности, сканеры (например `npm audit`, `pip-audit`, `bandit`, ESLint security-плагины) и security-заголовки в коде.
